### F-001: إدارة المستخدمين والمصادقة

**الأولوية:** P0 | **الحالة:** 🟡 معتمد | **المرحلة:** 1

#### الوصف
نظام تسجيل ومصادقة آمن متعدد الطرق مع التحكم في الصلاحيات بحسب الأدوار. هذا هو الأساس الذي يقوم عليه كل شيء آخر.

#### معايير القبول
- [ ] تسجيل بالبريد الإلكتروني/كلمة المرور مع رابط تفعيل البريد
- [ ] تسجيل دخول Google (OAuth 2.0)
- [ ] تسجيل دخول Apple (مطلوب بموجب سياسة App Store للـ iOS)
- [ ] تحقق اختياري برمز OTP للهاتف لحساب بريد/تواصل اجتماعي قائم؛ الحسابات المعتمدة على الهاتف فقط ممنوعة وفق OQ-001
- [ ] التسجيل وتسجيل الدخول وتحديث رمز الهوية عبر Firebase Auth في تطبيق Flutter، مع جلسات لكل جهاز يتحقق منها الخادم وتنتهي بعد 30 يوماً من عدم النشاط وتدعم تسجيل الخروج من الجهاز الحالي
- [ ] الملف الشخصي: الاسم، الصورة الرمزية (محفوظة في MinIO)، نبذة تعريفية، اللغة المفضلة
- [ ] استعادة كلمة المرور عبر البريد الإلكتروني
- [ ] حذف الحساب مع إتلاف البيانات (امتثالاً لإرشادات الخصوصية)
- [ ] تسجيل رمز الجهاز للإشعارات الفورية (FCM)

#### الاعتماديات
- لا يوجد (هذا هو الأساس)

### F-002: إدارة الحلقات

**الأولوية:** P0 | **الحالة:** 🟡 معتمد | **المرحلة:** 1

#### الوصف
الحلقة هي الوحدة التنظيمية الأساسية. تضم معلماً وطلاباً ومشرفين اختيارياً، مع جلسات ومحادثات وسجلات تقدم مرتبطة.

#### معايير القبول
- [ ] إنشاء حلقة: اسم (مطلوب)، وصف، قواعد، حد أعضاء (الافتراضي 50، الأقصى 200)
- [ ] توليد كود دعوة فريد من 8 أحرف تلقائياً عند الإنشاء
- [ ] رابط مشاركة عميق: `halaqaty.app/join/{code}`
- [ ] يمكن إعادة توليد الكود (يُبطل الكود القديم) من قِبل المعلم
- [ ] يمكن للطالب الانضمام لـ **5 حلقات** كحد أقصى في نفس الوقت
- [ ] يمكن للمعلم تعيين دور المشرف لأي عضو في أي وقت (قبل الجلسة، أثناءها، بعدها)
- [ ] يمكن سحب دور المشرف في أي وقت
- [ ] خصوصية الحلقة: **عامة** (تظهر في البحث/الاستكشاف) أو **خاصة** (بدعوة فقط)
- [ ] إعدادات الحلقة: اللغة، التخصيص الجنسي (ذكور/إناث/مختلط/غير محدد)
- [ ] يمكن للمعلم أرشفة الحلقة (يحفظ كل التاريخ، يمنع أي نشاط جديد)
- [ ] يمكن للمعلم حذف الحلقة (بتأكيد؛ يحذف جميع البيانات نهائياً)
- [ ] قائمة الأعضاء مع الأدوار مرئية لجميع أعضاء الحلقة

#### الأسئلة المفتوحة
- **OQ-004:** هل يجب أن يكون هناك دور "معلم مشارك" يختلف عن المشرف؟ بعض الحلقات بها معلمان مؤهلان.
- **OQ-005:** هل يمكن لطالب أن يكون مشرفاً في حلقة وطالباً في أخرى؟ (على الأرجح نعم — الأدوار لكل حلقة)
- **OQ-006:** ماذا يحدث للحلقة إذا حذف المعلم حسابه؟ نقل لمعلم آخر؟ أرشفة؟

#### قرارات التصميم
- **DD-005:** الأدوار خاصة بكل حلقة (محفوظة في جدول `circle_members`)، وليست عالمية. يمكن للمستخدم أن يكون معلماً في حلقة وطالباً في أخرى.
- **DD-006:** الحد الأقصى 5 حلقات للطالب هو سياسة مرنة في البداية. نراجعها بناءً على سلوك المستخدم.
- **DD-007 (مؤقت):** في MVP نعتمد على صلاحيات المعلم + المشرف، وتفاصيل دور "المعلم المشارك" تُؤجَّل لما بعد نتائج التجربة.

#### الحالات الحافة
- المعلم يدعو شخصاً عضواً بالفعل ← رسالة "أنت عضو بالفعل"، لا يُنشئ تكراراً
- الطالب يحاول الانضمام لحلقة سادسة ← رسالة خطأ تشرح الحد
- تصادم كود الدعوة (احتمال نادر جداً مع 8 أحرف) ← إعادة توليد تلقائي

#### الاعتماديات
- F-001 (مصادقة المستخدم)

### F-003: نظام طابور التسميع

**الأولوية:** P0 | **الحالة:** 🟡 معتمد | **المرحلة:** 2

#### الوصف
الميزة الأكثر تميزاً وفرادة في حِلْقَتي. طابور منظم وتفاعلي في الوقت الفعلي لتسميع الطلاب خلال الجلسات المباشرة. يحلّ محل الترتيب الشفهي الفوضوي الشائع في الحلقات اليوم.

#### لماذا هذه هي الميزة الأساسية؟

نقطة الألم الحالية: في حلقة قرآنية عبر الإنترنت، يقول المعلم شفهياً "الآن دور علي، ثم فاطمة، ثم عمر..." — هذا غير منظم، يصعب متابعته، ولا يُخلِّف أي سجل. حِلْقَتي يجعل الطابور مرئياً وتفاعلياً ومُوثَّقاً بالكامل.

#### حالات الطابور

```
                    ┌───────────────────────────────┐
                    │      آلة حالة الطابور          │
                    │                               │
  المعلم يُنشئ     │   ┌──────────┐                │
  جلسة ──────────►├──►│   فارغ   │                │
                    │   └─────┬────┘                │
                    │         │ الطلاب ينضمون       │
                    │         ▼                     │
                    │   ┌──────────┐                │
                    │   │ انتظار  │◄───────────────┐│
                    │   │    ⏳    │  تخطي/إعادة    ││
                    │   └─────┬────┘   ترتيب        ││
                    │         │                     ││
                    │         │ المعلم يبدأ الدور   ││
                    │         ▼                     ││
                    │   ┌──────────┐                ││
                    │   │ يُسمِّع │                ││
                    │   │    🎙️   │                ││
                    │   └─────┬────┘                ││
                    │         │ المعلم يُنهي الدور  ││
                    │         ▼                     ││
                    │ ┌──────────┐ ┌──────────┐    ││
                    │ │ اكتمل   │ │  تخطّى   │───┘│
                    │ │    ✅   │ │    ⏭️    │    │
                    │ └──────────┘ └──────────┘    │
                    │                               │
                    │  إعادة ضبط ────────────► فارغ │
                    └───────────────────────────────┘
```

#### نظام الجولات — المواصفة التفصيلية

كل جلسة تتكون من جولة واحدة أو أكثر. الجولة تُحدِّد:
- `رقم_الجولة` — 1، 2، 3، ...
- `نوع_الجولة` — حفظ_جديد | مراجعة | مراجعة_قديمة | اختبار
- `اسم_السورة` — مثال: "البقرة"
- `من_آية` — عدد صحيح، مثال: 1
- `إلى_آية` — عدد صحيح، مثال: 20

عند إعادة ضبط الطابور من قِبل المعلم:
1. تُختم جميع إدخالات الجولة الحالية نهائياً
2. يُنشأ سجل جولة جديد مع بيانات السورة والآية الجديدة
3. تُعاد حالات جميع الطلاب إلى ⏳ انتظار
4. يمكن إعادة ضبط ترتيب الطابور للجولة الجديدة

#### متطلبات المزامنة الفورية
- حالة الطابور يجب أن تكون مرئية لجميع المشاركين في نفس اللحظة
- الهدف: تأخر < 500 ميلي ثانية من إجراء المعلم حتى انعكاسه على جميع العملاء
- التقنية: بث WebSocket لجميع مشاركي الجلسة
- معالجة الانقطاع: يعرض العميل "جارٍ إعادة الاتصال..." ثم يعيد مزامنة حالة الطابور
- عدم التكرار: الأحداث المتكررة عبر WebSocket يجب ألا تُسبِّب تغييرات مزدوجة في الحالة

#### معايير القبول
- [ ] الطابور مرئي لجميع المشاركين في الوقت الفعلي عبر WebSocket
- [ ] 3 أوضاع ترتيب على الأقل: ترتيب الحضور، يدوي من المعلم، يدوي من المشرف
- [ ] بيانات لكل جولة: اسم السورة، من آية، إلى آية، نوع الجولة
- [ ] يمكن إعادة ضبط الطابور مرات غير محدودة في الجلسة
- [ ] عند بدء دور الطالب: يُرسَل إشعار فوري داخل التطبيق وبالدفع
- [ ] نمط التقييم قابل للضبط لكل حلقة (إلزامي أو اختياري لكل دور مكتمل)
- [ ] صلاحية نشر صوت الطالب تُدار لكل دور بواسطة المعلم (تفعيل عند بدء الدور ثم إلغاء بعده)
- [ ] حقل ملاحظات المعلم في كل إدخال تقييم
- [ ] سجل الجلسة الكامل يُحفظ بعد انتهائها
- [ ] يُعامَل المتأخرون عن الحضور بإضافتهم لنهاية طابور الجولة الحالية
- [ ] الطابور يتعامل مع انقطاع الشبكة بسلاسة (الحالة محفوظة من جانب الخادم)
- [ ] يمكن للطالب طلب تخطي/انسحاب مؤقت من دوره الحالي (مثل مشكلة ميكروفون أو ظرف طارئ) مع موافقة المعلم/المشرف

#### الأسئلة المفتوحة
- **OQ-007:** هل يمكن للطالب "الانسحاب" من جولة معينة؟ (مثلاً: "لم أتحضر للمراجعة اليوم")
- **OQ-008:** هل يُضاف مؤقت لكل طالب؟ (مثلاً: 5 دقائق كحد أقصى للتسميع)
- **OQ-009:** هل يمكن ضبط الطابور مسبقاً قبل بدء الجلسة؟
- **OQ-011:** هل يُضاف الطالب مرتين في نفس الجولة (مرة للحفظ الجديد، مرة للمراجعة)؟

#### قرارات التصميم
- **DD-005:** حالة الطابور مُخزَّنة في PostgreSQL (وليس في الذاكرة فقط) لضمان حفظ التاريخ وتمكين العملاء من استعادة الحالة عند إعادة الاتصال.
- **DD-006:** أحداث WebSocket هي آلية التوصيل، لكن PostgreSQL هو مصدر الحقيقة.
- **DD-007:** نمط التقييم يُضبط على مستوى الحلقة (إلزامي أو اختياري لكل دور مكتمل).
- **DD-008:** الانسحاب/التخطي المؤقت للطالب مسموح للأسباب التشغيلية ويُسجَّل في تاريخ الطابور.
- **DD-009:** الطالب المنضم متأخراً يُضاف لنهاية الجولة النشطة الحالية.

#### الاعتماديات
- F-001، F-002، F-005 (الجلسات المباشرة)، F-008 (الإشعارات)

### F-004: نظام المحادثات الفورية

**الأولوية:** P0 | **الحالة:** 🟡 معتمد | **المرحلة:** 1

#### الوصف
نظام رسائل متكامل داخل الحلقات يُحلُّ محل مجموعات واتساب وتيليغرام.

#### معايير القبول
- [ ] محادثة جماعية: واحدة لكل حلقة، جميع الأعضاء يشاركون
- [ ] رسائل مباشرة: معلم ↔ طالب؛ مشرف ↔ طالب
- [ ] **رسائل صوتية** — تسجيل داخل التطبيق، إرسال، عرض موجة الصوت، تشغيل؛ محفوظة في MinIO
- [ ] مرفقات صور: JPEG، PNG؛ حد أقصى 5MB للصورة
- [ ] مرفقات ملفات: PDF فقط (لصفحات المصحف، التمارين)؛ حد أقصى 10MB
- [ ] حالة الرسالة: مُرسَلة ✓ / مُستلَمة ✓✓ / مقروءة ✓✓ (أزرق)
- [ ] مؤشر الكتابة ("علي يكتب...")
- [ ] بحث نصي كامل في سجل المحادثات
- [ ] تثبيت الرسائل: المعلم/المشرف فقط؛ حد أقصى 5 مثبَّتة للحلقة
- [ ] الرد على رسالة محددة (يعرض معاينة مقتبسة)
- [ ] حذف الرسائل الخاصة في 10 دقائق؛ المعلم يحذف أي رسالة

#### الأسئلة المفتوحة
- **OQ-012:** هل يجب أن تكون هناك قنوات "إعلانات فقط" حيث يُرسِل المعلم فقط؟
- **OQ-013:** هل نُحدِّد الحد الأقصى لمدة الرسالة الصوتية؟ (مقترح: 5 دقائق)
- **OQ-014:** هل ندعم التفاعلات بالإيموجي؟

#### قرارات التصميم

- **DD-009:** لا تشفير شامل في الإصدار الأول (معقد مع رسائل المجموعات). التشفير أثناء النقل (TLS) كافٍ في V1.

### F-005: الجلسات المباشرة (LiveKit)

**الأولوية:** P0 | **الحالة:** 🟡 معتمد | **المرحلة:** 2

#### الوصف
جلسات صوتية فقط بلا حد زمني مدعومة بـ LiveKit (SFU مفتوح المصدر، WebRTC، مستضاف ذاتياً). الفيديو مؤجل لما بعد MVP عبر Feature Flag.

#### إعداد الصوت المُحسَّن للتلاوة القرآنية

تستخدم زووم وجوجل ميت معالجة صوتية مُحسَّنة للكلام العادي — مما قد يُشوِّه الخصائص الصوتية الدقيقة لتلاوة القرآن. حِلْقَتي يضبط LiveKit للحصول على جودة صوت مثالية للتلاوة:

| الإعداد | التطبيقات الاعتيادية | إعداد حِلْقَتي |
|---------|-------------------|--------------|
| الكودك | Opus ~32kbps | Opus 48–64kbps |
| إلغاء الضوضاء | مفعَّل | **مُعطَّل** (للحفاظ على دقة المخارج والتجويد) |
| التحكم التلقائي في الكسب | مفعَّل | **مُعطَّل** (صوت تسميع ثابت) |
| إلغاء الصدى | مفعَّل | مفعَّل (لا يزال ضرورياً) |

#### معايير القبول
- [ ] حزمة Flutter: `livekit_client` (الرسمية) مُدمَجة
- [ ] توليد الرمز (Token) حصرياً في خادم Go (لا من جانب العميل)
- [ ] صوت فقط في MVP (بدون خيار فيديو في التطبيق)
- [ ] بلا حد زمني
- [ ] تحكم المعلم: كتم الكل، كتم الأفراد، إخراج مشارك، قفل الغرفة
- [ ] رفع اليد: الطالب يضغط 🤚 ← يظهر في واجهة المعلم؛ متكامل مع طابور التسميع
- [ ] مشاركة الشاشة مؤجلة لما بعد MVP (ضمن نفس منظومة Feature Flags الخاصة بالفيديو)

### F-007: متابعة تقدم التحفيظ — مُعزَّزة

*(تعزيز لـ: متابعة تقدم التحفيظ | تُنجز أيضاً: المحتوى الطلابي لـ F-010)*

**الأولوية:** P1 | **الحالة:** 🟡 معتمد | **المرحلة:** 3

> **قرارات التصميم مُؤمَّنة 2026-06-30.** انظر [F-007-SPEC.md](../../engineering/design/F-007-SPEC.md) للمواصفات التقنية الكاملة.

#### الوصف

طبقة متكاملة لتتبع تقدم الطالب، مبنية على بيانات الجلسات وطابور التسميع الموجودة.

**الفرق الجوهري — حضر ≠ تلا:**
- **حضر (حضر):** `session_attendance.status = 'present'`
- **تلا / راجع:** له ≥1 `recitation_queue_entries` بحالة `completed` — الأدوار المُقيَّمة فقط (المتخطى والمنسحب لا يُحتسبان)

**تقييم مجزَّأ للسور الطويلة:** السور الطويلة كالبقرة تُقيَّم بنطاق الآيات (مُخزَّن في from_ayah/to_ayah). تعرض خريطة القرآن نسبة التغطية لكل سورة.

#### خريطة القرآن — 5 مستويات

| اللون | الحالة | المعنى |
|-------|--------|--------|
| 🟢 | `memorized` محفوظ | آخر سجل = حفظ جديد + درجة ممتاز أو جيد |
| 🟢⚠️ | `memorized_stale` محفوظ · يحتاج مراجعة | محفوظ + لا مراجعة منذ 30 يوماً |
| 🔵 | `in_revision` قيد المراجعة | آخر سجل = مراجعة |
| 🟡 | `needs_recap` يحتاج مراجعة | آخر درجة = يحتاج مراجعة أو إعادة |
| 🟠 | `in_progress` جزئي | لديه سجلات لكن لا يطابق أياً مما سبق |
| ⚪ | `not_started` لم يُبدأ | لا سجلات |

#### معايير القبول (مختصرة)

- [ ] إنشاء سجل `memorization_progress` آلياً عند كل إدخال بحالة `completed` فقط
- [ ] التمييز بين حضر فقط و تلا / راجع في كل جلسة
- [ ] `GET /students/me/progress` — خريطة القرآن 114 سورة (كل الحلقات مجمّعة)
- [ ] `GET /students/me/sessions/history` — سجل الجلسات مع حضر/تلا لكل جلسة
- [ ] `GET /students/me/progress/stats` — تحليلات: آيات أسبوعياً، معدل الحضور، معدل التسميع
- [ ] `GET /circles/{id}/progress` — المعلم: ملخص جميع الطلاب + علامة 🚩 (≥7 جلسات بدون تسميع)
- [ ] `GET /circles/{id}/surah-insights` — المعلم: السور مرتبة حسب الدرجات الضعيفة

#### الاعتماديات
- F-003 (طابور التسميع) — متطلب أساسي
- F-005 (الجلسات المباشرة) — متطلب أساسي
- F-010 (لوحات الطالب والمعلم) — F-007 تُوفِّر المحتوى الطلابي لـ F-010
