## 1. فلسفة النشر

**ابدأ بسيطاً. توسَّع عند الحاجة. لا تُعقِّد البنية مبكراً.**

استراتيجية نشرنا تقوم على المبادئ التالية:

1. **المرحلة الأولى بـ 8–12 دولار/شهر.** لن نستثمر في بنية تحتية معقدة قبل إثبات المنتج.
2. **Docker Compose أولاً.** سهل الإدارة، سهل التشخيص، كافٍ لمئات المستخدمين.
3. **Kubernetes عند الضرورة الحقيقية فقط.** عندما يصبح Docker Compose عائقاً حقيقياً.
4. **استضافة ذاتية أولاً، سحابة ثانياً.** Hetzner قبل AWS لكفاءة التكلفة. ننتقل لـ AWS/GCP فقط عند نفاد طاقة Hetzner.
5. **بلا قفل للمورِّد.** MinIO بدلاً من S3، LiveKit بدلاً من Twilio، Firebase فقط للمصادقة/الإشعارات.

## 2. المرحلة الأولى — MVP (10–50 مستخدم)

**الجدول الزمني:** الأشهر 1–5 | **التكلفة:** ~8–12 دولار/شهر

### البنية التحتية

**خادم Hetzner CX22 واحد:**

| المواصفة | القيمة |
|---------|--------|
| المزود | Hetzner Cloud |
| نوع الخادم | CX22 |
| المعالج | 2 AMD vCPU |
| الذاكرة | 4 GB RAM |
| التخزين | 40 GB NVMe SSD |
| عرض النطاق الترددي | 20 TB/شهر |
| الموقع | نورمبرغ، ألمانيا (تأخر منخفض لأوروبا ومنطقة MENA) |
| **التكلفة** | **~4.5–6 دولار/شهر** |

**تكاليف إضافية:**
- Cloudflare (الطبقة المجانية): DNS + SSL/TLS
- Firebase (خطة Spark المجانية): مصادقة + FCM (كافٍ لـ < 10,000 مستخدم نشط شهرياً)
- النطاق: ~12 دولار/سنة
- **المجموع: ~8–12 دولار/شهر** 🎯

### الخدمات على خادم المرحلة الأولى

```
╔═══════════════════════════════════════════════╗
║        Hetzner CX22 — خادم واحد             ║
║                                               ║
║  ┌──────────────────────────────────────────┐ ║
║  │          Nginx (البروكسي العكسي)          │ ║
║  │  halaqaty.app → حاوية Go API             │ ║
║  │  ws.halaqaty.app → Go WebSocket          │ ║
║  │  lk.halaqaty.app → حاوية LiveKit        │ ║
║  │  files.halaqaty.app → حاوية MinIO       │ ║
║  └──────────────────────────────────────────┘ ║
║                                               ║
║  ┌───────────┐  ┌───────────┐  ┌───────────┐ ║
║  │  Go API   │  │ LiveKit   │  │   MinIO   │ ║
║  │  + WS     │  │  Server   │  │   Server  │ ║
║  └───────────┘  └───────────┘  └───────────┘ ║
║                                               ║
║  ┌───────────────────────────────────────────┐ ║
║  │           PostgreSQL 16                   │ ║
║  │          (قاعدة البيانات الأساسية)         │ ║
║  └───────────────────────────────────────────┘ ║
╚═══════════════════════════════════════════════╝
```

### تقديرات طاقة المرحلة الأولى

| المورد | التقدير | ملاحظات |
|--------|---------|---------|
| جلسات مباشرة متزامنة | 2–5 | مُحدَّد بالذاكرة (LiveKit ~200MB لكل جلسة) |
| اتصالات WebSocket متزامنة | 100 | Go يتعامل معها بسهولة |
| اتصالات قاعدة البيانات | 50 | PostgreSQL على نفس الخادم |
| مستخدمون نشطون يومياً | 50 | هدف المرحلة الأولى |
| التخزين (MinIO) | < 10 GB | رسائل صوتية وصور؛ 40 GB SSD كافٍ |

### مخاطر المرحلة الأولى وتخفيفها

| الخطر | الاحتمال | التأثير | التخفيف |
|-------|---------|---------|---------|
| نفاد الذاكرة في الجلسات الكبيرة | منخفض | مرتفع | مراقبة؛ إضافة swap؛ ترقية لـ CX32 إذا لزم |
| توقف الخادم | متوسط | مرتفع | لقطات يومية (ميزة Hetzner، مجانية) |
| تشغيل LiveKit + Go + PostgreSQL على نفس الخادم | مقبول | متوسط | مقبول للنسخة التجريبية؛ نفصل في المرحلة 2 |

## 3. المرحلة الثانية — النمو (100–500 مستخدم)

**الجدول الزمني:** الأشهر 6–9 | **التكلفة:** ~23–30 دولار/شهر

### متى نتحرك للمرحلة الثانية؟

عند تحقق **أيٍّ** مما يلي:
- جلسات مباشرة متزامنة > 5 باستمرار
- استخدام RAM على CX22 > 70% باستمرار
- تدهور أوقات الاستجابة (P95 > 500 ميلي ثانية)
- التخزين يقترب من 35 GB

### البنية التحتية

**خادمان Hetzner:**

| الخادم | النوع | الدور | التكلفة |
|--------|-------|-------|---------|
| خادم التطبيق | CX32 (4 vCPU، 8 GB) | Go Backend + PostgreSQL + MinIO | ~10 دولار/شهر |
| خادم LiveKit | CX32 (4 vCPU، 8 GB) | LiveKit SFU (مخصص) | ~10 دولار/شهر |
| **Cloudflare** | مجاني | DNS + CDN + SSL | 0 دولار |
| **المجموع** | | | **~20–25 دولار/شهر** |

### لماذا نفصل LiveKit؟

LiveKit SFU مُكثِّف للمعالج وعرض النطاق الترددي خلال الجلسات النشطة. بفصله:
- لا يتأثر خادم التطبيق بارتفاع حمل الجلسات المفاجئ
- يمكن ترقية خادم LiveKit بشكل مستقل
- يمكن تقريب LiveKit جغرافياً من المستخدمين في المستقبل

### طاقة المرحلة الثانية

| المورد | التقدير |
|--------|---------|
| جلسات مباشرة متزامنة | 10–20 |
| مستخدمون نشطون يومياً | 200–500 |
| اتصالات WebSocket متزامنة | 500 |
| التخزين | 50–200 GB (أحجام Hetzner ~5 دولار/100GB) |

## 4. المرحلة الثالثة — التوسع (500–5,000 مستخدم)

**الجدول الزمني:** الأشهر 10–18 | **التكلفة:** ~100–200 دولار/شهر

### متى نتحرك للمرحلة الثالثة؟

عند تحقق **أيٍّ** مما يلي:
- جلسات مباشرة متزامنة > 20
- PostgreSQL يُصبح عنق الزجاجة (تأخر P95 > 100ms)
- خادم LiveKit واحد غير كافٍ لأوقات الذروة
- الحاجة لتحديثات بدون توقف (rolling updates)

### البنية التحتية: Kubernetes

**خيار A: Hetzner Kubernetes (HKS)** — موصى به (كفاءة تكلفة)
- 3 عقد: CX32 × 3 = ~30 دولار/شهر
- مستوى التحكم المُدار مجاناً
- Hetzner Load Balancer: ~6 دولار/شهر
- Hetzner Volumes لـ PostgreSQL: ~20 دولار/شهر
- **المجموع: ~60–80 دولار/شهر**

**ما تُتيحه Kubernetes:**
- نشر متجدد بدون توقف
- توسع أفقي تلقائي لحجرات Go
- فحوصات الصحة وإعادة التشغيل الآلي
- أحجام ثابتة لبيانات PostgreSQL وMinIO

## 5. المرحلة الرابعة — العالمية (5,000+ مستخدم)

**الجدول الزمني:** الشهر 18+ | **التكلفة:** 500+ دولار/شهر

### البنية التحتية: AWS / GCP متعدد المناطق

في هذا الحجم، تخدم المنصة مستخدمين عبر قارات متعددة. التأخر لخادم الوسائط (LiveKit) يُصبح حرجاً لجودة الصوت.

```
مستخدم في مصر ──────────────────────────► عقدة LiveKit (فرانكفورت/البحرين)
مستخدم في ماليزيا ──────────────────────► عقدة LiveKit (سنغافورة)
مستخدم في أمريكا ───────────────────────► عقدة LiveKit (فيرجينيا)

جميع عقد LiveKit → Go Backend → PostgreSQL (الأساسي في أوروبا)
```

## 6. إعداد Docker Compose

يوضح الإعداد التالي هيكل Docker Compose للمرحلة الأولى:

```yaml
# docker-compose.yml (المرحلة الأولى)
version: '3.8'

services:
  # خادم Go الخلفي (REST API + WebSocket)
  api:
    image: halaqaty/api:latest
    restart: always
    ports:
      - "8080:8080"
    environment:
      - DB_URL=${DB_URL}
      - FIREBASE_PROJECT_ID=${FIREBASE_PROJECT_ID}
      - LIVEKIT_API_KEY=${LIVEKIT_API_KEY}
      - LIVEKIT_API_SECRET=${LIVEKIT_API_SECRET}
      - LIVEKIT_HOST=livekit:7880
      - MINIO_ENDPOINT=minio:9000
      - MINIO_ACCESS_KEY=${MINIO_ACCESS_KEY}
      - MINIO_SECRET_KEY=${MINIO_SECRET_KEY}
    depends_on:
      - postgres
      - minio
    networks:
      - halaqaty

  # قاعدة بيانات PostgreSQL
  postgres:
    image: postgres:16-alpine
    restart: always
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      - POSTGRES_DB=halaqaty
      - POSTGRES_USER=${DB_USER}
      - POSTGRES_PASSWORD=${DB_PASSWORD}
    networks:
      - halaqaty

  # خادم LiveKit SFU
  livekit:
    image: livekit/livekit-server:latest
    restart: always
    ports:
      - "7880:7880"
      - "7881:7881"
      - "50000-60000:50000-60000/udp"
    volumes:
      - ./livekit.yaml:/etc/livekit.yaml
    command: --config /etc/livekit.yaml
    networks:
      - halaqaty

  # MinIO (تخزين الملفات)
  minio:
    image: minio/minio:latest
    restart: always
    command: server /data --console-address ":9001"
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - minio_data:/data
    environment:
      - MINIO_ROOT_USER=${MINIO_ACCESS_KEY}
      - MINIO_ROOT_PASSWORD=${MINIO_SECRET_KEY}
    networks:
      - halaqaty

  # Nginx (البروكسي العكسي)
  nginx:
    image: nginx:alpine
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - api
      - livekit
      - minio
    networks:
      - halaqaty

volumes:
  postgres_data:
  minio_data:

networks:
  halaqaty:
    driver: bridge
```

**مقاييس أساسية للمراقبة:**

| المقياس | عتبة التنبيه | الإجراء |
|---------|-------------|---------|

| اتصالات WebSocket | > 1000 (المرحلة 2) | توسيع Go Backend |
| جلسات LiveKit النشطة | > 15 (CX32 المرحلة 2) | إضافة عقدة LiveKit |
| استعلامات PostgreSQL/ثانية | > 500 | إضافة نسخة قراءة |
| استخدام RAM | > 80% | ترقية الخادم أو التوسع |
| استخدام القرص | > 75% | إضافة حجم تخزين |
| معدل الأخطاء (5xx) | > 1% | تحقيق فوري |

**التنبيهات:** Grafana AlertManager → إشعار بوت Telegram لقناة فريق التطوير.

## 8. استراتيجية النسخ الاحتياطي

### نسخ احتياطية لقاعدة البيانات

**المرحلة الأولى (Docker Compose):**
```bash
# مهمة cron يومية الساعة 2:00 صباحاً UTC
0 2 * * * docker exec halaqaty_postgres_1 \
  pg_dump -U halaqaty halaqaty | \
  gzip > /backups/halaqaty_$(date +%Y%m%d).sql.gz

# التدوير: احتفاظ بـ 7 أيام محلياً، رفع لـ Hetzner Object Storage
0 3 * * * rclone copy /backups/ hetzner:halaqaty-backups/
find /backups/ -mtime +7 -delete
```

**المرحلة الثانية+:** استخدام أرشفة PostgreSQL المستمرة (WAL shipping) للاسترداد بنقطة زمنية.

### سياسة الاحتفاظ بالنسخ الاحتياطية

| نوع النسخ | مدة الاحتفاظ | الموقع |
|----------|------------|--------|
| نسخة PostgreSQL يومية | 7 أيام | Hetzner Object Storage |
| نسخة PostgreSQL أسبوعية | 4 أسابيع | Hetzner Object Storage |
| نسخة PostgreSQL شهرية | 12 شهراً | Hetzner Object Storage |
| لقطة خادم Hetzner | 3 لقطات | Hetzner (دوران تلقائي) |
| رسائل MinIO الصوتية | حتى حذفها من المستخدم | MinIO (حجم الخادم) |

### إجراءات الاسترداد

**السيناريو 1: فشل الخادم (المرحلة الأولى)**
1. توفير CX22 جديد على Hetzner
2. الاستعادة من آخر لقطة Hetzner (نقطة استعادة: 24 ساعة)
3. إذا كانت اللقطة غير متاحة، استعادة PostgreSQL من النسخة اليومية
4. تحديث Cloudflare DNS لعنوان IP الجديد

**السيناريو 2: تلف البيانات**
1. استعادة PostgreSQL من آخر نسخة احتياطية سليمة
2. استرداد بنقطة زمنية متاح من المرحلة الثانية+

## 9. SSL/TLS والنطاق

### إعداد DNS (Cloudflare)

```
halaqaty.app         A      → IP الخادم (محجوب بـ Cloudflare ✅)
www.halaqaty.app     CNAME  → halaqaty.app (محجوب ✅)
api.halaqaty.app     A      → IP الخادم (محجوب ✅)
lk.halaqaty.app      A      → IP خادم LiveKit (DNS فقط ⚡)
files.halaqaty.app   A      → IP الخادم (محجوب ✅)
```

**ملاحظة مهمة:** يجب أن يكون LiveKit "DNS فقط" (غير محجوب) لأن WebRTC يتطلب اتصالات UDP مباشرة — بروكسي Cloudflare لا يدعم UDP.

### SSL/TLS

- **halaqaty.app, api.halaqaty.app, files.halaqaty.app:** Cloudflare يدير SSL (مجاني، تلقائي)
- **lk.halaqaty.app:** Let's Encrypt عبر certbot (اتصال مباشر، يتجاوز بروكسي Cloudflare)
- الحد الأدنى لإصدار TLS: 1.2
- HSTS: `Strict-Transport-Security: max-age=31536000; includeSubDomains`

### إعدادات Cloudflare

- **الأمان:** Bot Fight Mode مفعَّل، حماية DDoS (تلقائية)
- **الأداء:** تخزين مؤقت للأصول الثابتة فقط؛ API في وضع "تجاوز" التخزين المؤقت
- **WebSocket:** مفعَّل (مطلوب لمميزاتنا الفورية)

## 10. خط أنابيب CI/CD

### المرحلة الأولى: خط بسيط (GitHub Actions)

```yaml
# .github/workflows/deploy.yml
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: بناء خادم Go
        run: |
          go build -o halaqaty-api ./cmd/api
          
      - name: بناء صورة Docker
        run: |
          docker build -t halaqaty/api:${{ github.sha }} .
          docker tag halaqaty/api:${{ github.sha }} halaqaty/api:latest
          
      - name: رفع للسجل
        run: docker push halaqaty/api:latest
        
      - name: النشر على الخادم
        run: |
          ssh deploy@${{ secrets.SERVER_IP }} \
            "cd /app && docker-compose pull && docker-compose up -d"
```
