# F-006 Research and Decisions

**Date:** 2026-09-27 | **Sources:** [spec](spec.md), ADR-016, ADR-025, `backend/migrations/000016_live_sessions.up.sql`, existing session service/repository, canonical OpenAPI, architecture and MVP register.

| Question | Decision and reason | Alternative rejected |
|---|---|---|
| Infinite recurrence | Generate only a caller-requested month, using each rule's stored duration to calculate a lookback and arithmetic jumps from its anchor. Include persisted moved/history rows. This includes long occurrences starting in earlier months without iterating from a distant anchor. | Prebuild a fixed 90-day horizon or assume only one overnight day of spillover. |
| Stable identity and history | Use `(schedule_id, original_local_date)` as the logical occurrence key. Version recurrence rules by effective local date so prior virtual calendar history remains reproducible. Persist an occurrence row only for exception, cancellation or activation; unique keys protect retries. | Use only generated timestamps, which change after editing or DST resolution, or overwrite a rule and lose past virtual occurrences. |
| Recurrence model | `weekday_pattern` (cadence 1 or 2 weeks + weekday set), `interval` (positive count + day/week unit), or `selected_dates` (deduplicated local dates). First planned local date anchors cadence. | A separate recurrence engine/library or a weekly-only table. No new dependency is needed for the accepted subset. |
| Time model | Persist entered local start/end clock times, 1–44,640 minute elapsed duration, IANA planning zone, anchor date, and optional inclusive recurrence end date. The 31-day length ceiling bounds month-query work, without limiting when a plan may start; F-005 live limits still apply. The end clock equals start plus duration by nominal 24-hour arithmetic; resolved end remains start plus elapsed duration in UTC, so DST may change its displayed clock time. Store viewer IANA timezone in the existing profile with `UTC` backfill and additive `/auth/me` read/update. | Persist only UTC for the series, infer the viewer zone from device settings, discard the entered local end clock, or allow unbounded overlapping planned lengths. |
| Session integration | F-005 `sessions` remains the live state record. Reuse its transaction body so recurring materialization and F-005 start occur under one parent-schedule lock/transaction; cancel/series edit takes the same lock and checks both virtual exception and materialized detail. One-offs serialize on their session row. | Nested start transactions, which release the occurrence lock between materialization and activation; a new `cancelled` F-005 status. |
| Overlap warnings | Preview only the first 31 local days of an open-ended proposal, or all selected finite dates. Warnings carry authorized circle identity and overlapping UTC interval. On write, recompute warnings and require the manager to reconfirm any new/changed warning ID; repeat evaluation for viewed months. | Exhaustively scan open-ended recurrence, silently accept new conflicts with a stale boolean, or block manager choice. |
| Attendance input | F-005 presence row's `first_joined_at` supplies the first authorized participation time; one row per user/session already collapses reconnects. Snapshot active students at start; upsert later-enrolled eligibility during authorized join/presence, before a membership row can be removed. | Reconstruct eligibility from `circle_members` at session end, infer duration from join/leave snapshots, or mutate raw presence. |
| Attendance override | Base classification and manual correction audit are separate; latest valid correction wins, so reclassification never erases a teacher decision. | Store only the final status and lose audit/replay provenance. |
| Notifications | Publish only a stable eligibility/query boundary for F-008; no FCM calls or notification table changes in F-006. | Build a second delivery pipeline. |
| Realtime | No new WebSocket event in the pilot; clients refetch after their own mutation and on resume. | A calendar event stream with new ordering/recovery semantics. |

## Source checks and remaining dependency

- `000016_live_sessions.up.sql` already has `sessions.scheduled_at`, `actual_start`, `actual_end` and `session_participant_presence.first_joined_at`; it has no `schedules` or `session_attendance` table. F-005 status check permits only `scheduled`, `active`, `ended`.
- The canonical OpenAPI now contains the approved F-006 schedule contract, but no schedule handler exists. Contract tests must verify implementation parity.
- `circle_members` is the role source; historical records may remain after revocation, but reads must reauthorize current membership. Archived circles are read-only.
- ADR-026 was accepted by Karim on 2026-09-27; architecture and canonical REST contract are synchronized. Executable migration and API code remain to be implemented and tested.
- F-008 is Proposed. SC-009 cannot be marked complete during an F-006-only pilot.
